# FusionMetrics Data Model v2 Spec

## 1. Purpose

This document defines the target Phase 2 data model for FusionMetrics. It is a
planning/spec artifact only. It does not approve generated data edits, scraping,
backend work, or UI implementation.

The v2 model should let FusionMetrics expand from a JustTCG-only FB01-FB09 MVP
into broader TCG market intelligence while preserving the current trust rule:
make FusionMetrics unable to lie by accident.

## 2. Current v1 Baseline

| Current artifact | Shape | Owner | Notes |
|------------------|-------|-------|-------|
| `src/cardData.json` | Array of card metadata | Generated by card scripts | Active scope is FB01-FB09. Do not hand-edit. |
| `src/livePrices.json` | Array of `{ cardCode, marketPrice, timestamp }` | JustTCG pipeline | Current prices only. Split shape is required. |
| `public/priceHistory30d.json` | Object `cardCode -> [{ p, t }]` | JustTCG pipeline | Real 30d history, lazy-loaded by CardDetail. |
| `public/priceUpdateLog.json` | Refresh metadata object | JustTCG pipeline | Powers provenance footer/modal. |
| `fw-watchlist-v2` | localStorage object | Browser-local user data | Local-only portfolio fields. |

Current `cardData.json` fields:

- `code`
- `set`
- `setName`
- `rarity`
- `rarityName`
- `rarityColor`
- `pullRate`
- `character`
- `icon`
- `googleTrends`
- `name`
- `cardColor`
- `cardType`
- `trait`
- `verified`
- `image`

Current app-derived card fields in `src/data.js` include pricing/model fields
such as `marketPrice`, `predictedPrice`, `delta`, `priceStatus`,
`confidence`, `hasLivePrice`, and `priceTimestamp`. Those are runtime read
model fields, not source card metadata.

## 3. Modeling Principles

- Keep source data separate from derived analytics.
- Keep observed market data separate from modeled estimates.
- Keep raw, graded, sealed, promo, and alternate-art markets separate unless a
  source explicitly proves they are the same variant.
- Every external market observation needs source, timestamp/date, and
  confidence metadata.
- Every generated artifact needs a validator before UI consumption.
- Static JSON remains the default until backend trigger criteria are met.
- No field should imply guaranteed profit, sale value, or investment advice.

## 4. Type Conventions

| Type | Meaning |
|------|---------|
| `string` | Non-empty string unless marked nullable. |
| `number` | Finite JavaScript number. Prices must be positive unless explicitly allowed as zero. |
| `integer` | Finite integer. |
| `boolean` | `true` or `false`. |
| `isoDate` | `YYYY-MM-DD`. |
| `isoDateTime` | ISO 8601 timestamp. |
| `epochSeconds` | Positive Unix timestamp in seconds. |
| `enum[...]` | One of the listed values. |
| `array<T>` | Array of values of type `T`. |
| `nullable<T>` | `T` or `null`. |

## 5. Entity: `cards`

Canonical card identity and static metadata.

| Field | Type | Required | Source owner | Notes |
|-------|------|----------|--------------|-------|
| `cardCode` | string | Yes | Card metadata pipeline | Canonical display/code key. Current v1 maps from `code`. |
| `name` | string | Yes | Card metadata pipeline | Printed card name. |
| `setCode` | string | Yes | Card metadata pipeline | Current v1 maps from `set`; future allows `SB01`, `SB02`, promos. |
| `setName` | string | Yes | Card metadata pipeline | Printed set/product name. |
| `rarity` | string | Yes | Card metadata pipeline | Current values include `L`, `C`, `UC`, `R`, `SR`, `SCR`; future may add `SPR`, `GDR`, promo-specific rarities after validator update. |
| `rarityName` | string | Recommended | Card metadata pipeline | Human label. |
| `color` | nullable<string> | Recommended | Card metadata pipeline | Current v1 maps from `cardColor`. |
| `type` | nullable<string> | Recommended | Card metadata pipeline | Current v1 maps from `cardType`. |
| `traits` | array<string> | Recommended | Card metadata pipeline | Current v1 has `trait` as a slash-delimited string; v2 should normalize to an array. |
| `character` | nullable<string> | Recommended | Card metadata pipeline | `null` is valid for Extra cards or ambiguous cards. |
| `imageUrl` | nullable<string> | Recommended | Image pipeline | Current v1 maps from `image`; licensing/source must be documented. |
| `isVerified` | boolean | Yes | Card metadata pipeline | Current v1 maps from `verified`. |
| `sourceRefs` | array<string> | Recommended | Card metadata pipeline | URLs or source IDs that support the card metadata. |
| `tags` | array<string> | Optional | Manual metadata | General non-premium tags. |
| `premiumFlags` | array<string> | Optional | Premium metadata | Prefer storing in `premium_metadata` and denormalizing later only if needed. |

Migration notes:

- Keep `cardCode` stable and unique.
- Do not rename existing card codes without an alias/migration plan.
- Do not add SB/promo set codes until validators understand them.
- Convert `trait` to `traits` only in a staged artifact first.

## 6. Entity: `sets`

Set, starter deck, promo group, or sealed-product family metadata.

| Field | Type | Required | Source owner | Notes |
|-------|------|----------|--------------|-------|
| `setCode` | string | Yes | Card metadata pipeline | Examples: `FB01`, `SB01`, future promo group code. |
| `name` | string | Yes | Card metadata pipeline | Printed product/set name. |
| `releaseDate` | nullable<isoDate> | Recommended | Manual/Bandai source | Use `null` when unknown. |
| `productType` | enum[`booster`, `starter`, `promo`, `event`, `sealed`, `other`] | Yes | Manual/spec | `FB` sets are `booster`; `SB` sets are `starter`. |
| `cardCount` | nullable<integer> | Recommended | Card metadata pipeline | Expected total if known. |
| `sealedProducts` | array<string> | Optional | Sealed product spec | Product codes linked to this set. |
| `dataCoverage` | object | Recommended | Derived validator | Counts for cards, live prices, history, images, premium metadata. |
| `sourceRefs` | array<string> | Recommended | Manual/Bandai source | Source URLs or source IDs. |

## 7. Entity: `premium_metadata`

Premium chase metadata. This is not a buy/sell score.

| Field | Type | Required | Source owner | Notes |
|-------|------|----------|--------------|-------|
| `cardCode` | string | Yes | Manual metadata | Must exist in `cards`. |
| `premiumFlags` | array<enum> | Yes | Manual metadata | See `docs/premium-metadata-schema.md` § 5 for the canonical vocabulary. |
| `collectorTags` | array<string> | Optional | Manual metadata | Character tier, art appeal, nostalgia, fusion, villain/hero, set chase role. |
| `riskTags` | array<enum> | Optional | Manual/derived | See `docs/premium-metadata-schema.md` § 7 for the canonical vocabulary. |
| `gradeUpside` | object | Optional | Graded comps later | Raw/graded spread references and confidence; no guarantee language. |
| `confidence` | enum[`high`, `medium`, `low`] | Yes | Manual metadata | Confidence in metadata classification, not price outcome. |
| `sourceRefs` | array<string> | Required | Manual metadata | At least one source reference. |
| `notes` | nullable<string> | Optional | Manual metadata | Short rationale. |
| `updatedAt` | isoDateTime | Yes | Manual metadata | Last metadata review timestamp. |

Rules:

- No hype-only scoring.
- No guaranteed-return language.
- Do not show premium badges in UI until this artifact and validator exist.

## 8. Entity: `card_market_snapshots`

Latest observed price snapshot by card/source/variant/condition.

| Field | Type | Required | Source owner | Notes |
|-------|------|----------|--------------|-------|
| `cardCode` | string | Yes | Market source/importer | Must exist in `cards`. |
| `source` | enum[`justtcg`, `ebay`, `tcgplayer`, `pricecharting`, `cardmarket`, `manual`, `other`] | Yes | Source/importer | `justtcg` is current active source. |
| `price` | number | Yes | Source/importer | Positive market price. |
| `currency` | string | Yes | Source/importer | Use ISO currency code, e.g. `USD`. |
| `timestamp` | isoDateTime | Yes | Source/importer | Observation time. |
| `condition` | nullable<string> | Recommended | Source/importer | Example: `Near Mint`; normalize later. |
| `variant` | nullable<string> | Recommended | Source/importer | Base, alt art, manga, promo, reprint, etc. |
| `rawOrGraded` | enum[`raw`, `graded`, `sealed`, `unknown`] | Yes | Source/importer | Prevent raw/graded contamination. |
| `confidence` | enum[`high`, `medium`, `low`, `excluded`] | Yes | Source/importer/QA | Reflects match confidence. |
| `sourceUrl` | nullable<string> | Recommended | Source/importer | Required for manual external snapshots. |

Current mapping:

- `src/livePrices.json` can be interpreted as `source = justtcg`,
  `rawOrGraded = raw`, `condition = Near Mint or source default if known`,
  `variant = source default`, `confidence = medium`.
- Do not change the active file shape yet.

## 9. Entity: `price_history`

Historical price observations by card/source.

| Field | Type | Required | Source owner | Notes |
|-------|------|----------|--------------|-------|
| `cardCode` | string | Yes | Source/importer | Must exist in `cards`. |
| `source` | enum[`justtcg`, `ebay`, `tcgplayer`, `pricecharting`, `cardmarket`, `manual`, `other`] | Yes | Source/importer | Current public artifact is JustTCG only. |
| `date` | isoDate | Yes | Source/importer | Day bucket for history views. |
| `price` | number | Yes | Source/importer | Positive price. |
| `volume` | nullable<number> | Optional | Source/importer | Sale count or listing count if available. |
| `confidence` | enum[`high`, `medium`, `low`] | Yes | Source/importer/QA | Confidence in source/match. |
| `variant` | nullable<string> | Recommended | Source/importer | Needed before cross-source history. |
| `condition` | nullable<string> | Recommended | Source/importer | Needed before cross-source history. |

Current mapping:

- `public/priceHistory30d.json` maps to `source = justtcg`; `p` maps to
  `price`; `t` maps to `date` after converting epoch seconds.
- Keep the compact public artifact until a v2 history artifact and validator
  are explicitly approved.

## 10. Entity: `ebay_sold_comps`

Manual or API-sourced sold-comps observations. Start manual CSV first.

| Field | Type | Required | Source owner | Notes |
|-------|------|----------|--------------|-------|
| `listingId` | string | Yes | Manual/API import | Unique per eBay listing. |
| `cardCode` | string | Yes | Manual/API import | Must exist in `cards`; use review queue for unknowns. |
| `title` | string | Yes | Manual/API import | Raw listing title. |
| `soldPrice` | number | Yes | Manual/API import | Positive sold amount excluding shipping unless source says otherwise. |
| `shipping` | number | Recommended | Manual/API import | Use `0` only when confirmed free/included. |
| `currency` | string | Yes | Manual/API import | ISO currency code. |
| `soldDate` | isoDate | Yes | Manual/API import | Sale date. |
| `condition` | nullable<string> | Recommended | Manual/API import | Raw listing/source condition. |
| `rawOrGraded` | enum[`raw`, `graded`, `sealed`, `unknown`] | Yes | Manual/API QA | Must be reviewed. |
| `gradeCompany` | nullable<enum[`PSA`, `BGS`, `CGC`, `TAG`, `other`]> | Required if graded | Manual/API QA | Null for raw. |
| `grade` | nullable<string> | Required if graded | Manual/API QA | Preserve source grade text. |
| `variantMatch` | enum[`exact`, `likely`, `ambiguous`, `mismatch`, `excluded`] | Yes | Manual/API QA | Core anti-contamination field. |
| `confidence` | enum[`high`, `medium`, `low`, `excluded`] | Yes | Manual/API QA | Do not use excluded rows in analytics. |
| `outlierFlag` | boolean | Yes | Manual/API QA | Mark before aggregate metrics. |
| `sourceUrl` | string | Yes | Manual/API import | Required for traceability. |
| `notes` | nullable<string> | Optional | Manual/API QA | Short rationale. |

Rules:

- No automation until source approval checklist is complete.
- Do not mix raw and graded comps in one aggregate.
- Do not include lots, proxies, custom cards, unclear variants, or damaged
  cards without explicit flags.

## 13. Entity: `source_confidence`

Derived summary describing how trustworthy a card's market picture is. Canonical schema lives in `docs/source-confidence-spec.md`; this section is a summary view.

| Field | Type | Required | Source owner | Notes |
|-------|------|----------|--------------|-------|
| `cardCode` | string | Yes | Derived validator/importer | Must exist in `cards`. |
| `overall` | enum[`high`, `medium`, `low`, `unknown`] | Yes | Derived/QA | User-facing confidence label. |
| `score` | integer 0–100 | Optional | Derived | Internal display helper. Must be paired with label and flags. |
| `components` | object | Yes | Derived | Breakdown with `sourceAgreement`, `freshness`, `volume`, `variantClarity`, `outlierRisk`. See `docs/source-confidence-spec.md` § 7 for the per-component enums. |
| `flags` | array<enum> | Yes | Derived/QA | Specific cautions. See `docs/source-confidence-spec.md` § 8 for the canonical vocabulary. |
| `summary` | string | Recommended | Derived/QA | Short human-readable reason. |
| `sourceRefs` | array<string> | Recommended | Derived/QA | Source IDs/artifacts used to compute confidence; required for manual-source rows. |
| `updatedAt` | isoDateTime | Yes | Derived | Last computation or review timestamp. |

Rules:

- Source confidence is data-quality, not investment-quality.
- Hard-block flags prevent `overall = high` — see `docs/source-confidence-spec.md` § 9 for the list.
- Manual-source rows require `sourceRefs`.

See `docs/source-confidence-spec.md` for the full vocabulary, scoring model, and validation requirements.

## 14. Entity: `watchlist_positions`

Current state remains local browser storage only.

Current localStorage shape:

```js
{
  version: 2,
  items: {
    "FB01-001": {
      cardCode: "FB01-001",
      quantity: 1,
      entryPrice: 0.42,
      addedAt: "2026-05-01T12:00:00.000Z"
    }
  }
}
```

Future cloud shape should preserve:

- `userId`
- `cardCode`
- `quantity`
- `entryPrice`
- `addedAt`
- `updatedAt`
- optional `portfolioId`

Rules:

- Do not add cloud storage until accounts/backend are approved.
- Do not store derived values like P/L; recompute from current price.
- Preserve cautious copy: current value is based on current FusionMetrics
  price, and EST rows use model-estimated prices.

## 16. Migration Plan

1. Keep v1 files unchanged.
2. Complete specs for premium metadata, SB staging, eBay comps, source
   confidence, graded comps, sealed products, and expanded validation.
3. Add staging paths only after user approval.
4. Add tiny fixtures only after schemas are reviewed.
5. Build validators before any generated artifact is consumed by UI.
6. Generate read-only public artifacts.
7. Add UI only after artifacts exist and validation is strict.
8. Consider backend only when trigger criteria are met.

## 17. Validation Expectations

Future validators should enforce:

- Required fields and enum vocabularies.
- No duplicate primary keys.
- Referenced `cardCode` exists in canonical cards.
- Referenced `setCode` exists in canonical sets.
- Prices are finite positive numbers.
- Timestamps/dates are valid.
- eBay comps include `sourceUrl`.
- Raw and graded comps are separated.
- `variantMatch = excluded` or `confidence = excluded` rows are not used in
  aggregate analytics.
- Generated artifacts do not weaken the existing `verify-data` split-shape
  contract.

Current validation remains:

```bash
git diff --check
node scripts/verify-data.js
```

## 18. Open Questions

- What exact set-code pattern should starter decks use: `SB01`, `SB02`, or a
  broader product-code namespace?
- Should promos live under original printed card codes, separate promo set
  codes, or an alias table?
- Which image source is rights-safe enough for public beta?
- Which sold-comp source should be sampled first: manual eBay, PriceCharting,
  TCGplayer-visible data, or another public reference?
- What source variance threshold should mark `sourcesAgree = false`?
- What minimum comp count is required before manipulation risk can be anything
  other than `unknown`?
